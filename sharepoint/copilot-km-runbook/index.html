Copilot in SharePoint and OneDrive

Knowledge management guide and runbook

As of
21 September 2026
Owner
Steven, Financial Systems Analyst

1Purpose and scope

Copilot in SharePoint and OneDrive answers only as well as the content, permissions and structure it can reach. This guide sets the PIC standards that make that content trustworthy, and the runbook that keeps it that way.

Audience: PIC site owners, the knowledge owner, content authors (coordinators, analysts) and anyone building a SharePoint agent on PIC content.

In scope

  • The single PIC SharePoint Online site and its libraries (Knowledge Base, Governance, Reports, Operations areas)
  • PIC members' OneDrive, where working drafts live before publication
  • SharePoint agents and Copilot chat grounded on PIC libraries (including the JUAS Knowledge Base agent)
  • Migration of legacy content from the shared network drive (roughly 10 to 100 GB)

Out of scope

  • Power Apps or flows beyond the SharePoint-native exception (see next section)
  • Content on the on-premises host hydroshare.bchydro.bc.ca until Graph indexing is confirmed
  • SAP, which stays manual

Operating rule: if a person should not act on a document, Copilot must not be able to find it. Every standard below serves that rule.

2BC Hydro constraints

Citizen development on Power Platform is not permitted at BC Hydro, with one exception: apps and flows created from a SharePoint Online list or library that interact only with SharePoint. Everything in this runbook stays inside that boundary. (Source: BC Hydro Power Platform governance page, summarized 2026-08-17 in project file 2026-08-17-00-copilot-bch-restrictions.md.)

  • Governance automation (review reminders, expiry flags) must be SharePoint-triggered flows or built-in library features, not portal flows.
  • The Outlook notification connector is an open question with the IT Advisor; until answered, use SharePoint alerts or list rules for notifications.
  • Anything needing more than SharePoint goes to the IT Advisor as a written use case before build starts.

Admin and owner controls that matter

  • Set-SPOTenant -KnowledgeAgentScope (AllSites, IncludeSelectedSites, ExcludeSelectedSites, NoSites) controls where Copilot in SharePoint appears; the site list caps at 100 URLs.
  • Restricted Content Discovery removes Copilot in SharePoint, AI actions and the Agent icon from a site, and keeps its content out of Copilot and org-wide search, without changing access.
  • Site AI settings let the owner pick the main agent and hide the Copilot button from visitors.
  • Agents live as .agent files under Site Assets > Copilots (approved ones under Site Assets > Copilots > Approved); they carry version history.
  • Preview usage limits apply per user per day and week; Microsoft can change them and the underlying model without notice.

4Knowledge management principles

Seven rules govern every PIC document Copilot can reach. When a rule conflicts with convenience, the rule wins.

  1. One source of truth per topic. Each process, rate, rule or reference has exactly one Published document in the Knowledge Base. Copies elsewhere are deleted or linked, never duplicated.
  2. Draft in OneDrive, publish in SharePoint. Working drafts live in the author's OneDrive or a draft folder excluded from agents. Only Published documents live where agents ground.
  3. Status is metadata, not a filename. Status, Owner, Review Date and Content Type are library columns. Words like FINAL or v3 in filenames are prohibited.
  4. Permissions are the only access control. Copilot surfaces whatever a user can open. Fix oversharing at the permission level before enabling any agent; never rely on an agent's scope to hide content.
  5. Business rules as data. Rates, GL mappings, approval limits and order reasons live in SharePoint lists, not in prose or flow logic, so agents and flows read the same values.
  6. Superseded content leaves the grounding path. When a document is replaced, it moves to 99_Archive (excluded from agents) the same day.
  7. Every answer is cited and verified. Copilot output is a draft. Users open the cited source before acting on any figure, GL code, limit or deadline.

5Content and library standards

Copilot retrieves passages, not folders, so each document must stand on its own: a clear title, a one-paragraph summary, defined terms and a named owner.

Knowledge Base library taxonomy (adopted from the JUAS Knowledge Base design)

Folder Holds In agent grounding
00_Overview Scope, glossary, who-to-ask Yes
01_Core Processes End-to-end process descriptions Yes
02_Reference Data Rates, codes, mappings (prefer lists) Yes
03_Systems and Interfaces JUAS, SAP touchpoints, SharePoint lists Yes
04_Work Instructions Step-by-step procedures Yes
05_Policies and Governance Agreements (JOUA), approval limits, controls Yes
06_Future State - Draft Proposed designs No
07_Review Required Content awaiting validation No
99_Archive Superseded or retired content No

Excluded folders stay out of every agent's source list. Where Copilot in SharePoint's site-wide scope would still reach them, place 06, 07 and 99 in a separate library or site that is excluded (Setup step 4).

Required library columns

Column Type Rule
Status Choice: Draft, In Review, Published, Archived Only Published sits in grounded folders
Owner Person One named person, not a group
Review Date Date 12 months after publish by default; 6 months for rates and limits
Content Type Choice: Process, Work Instruction, Reference, Policy, Overview Drives agent filtering and review cadence
Applies To Choice: Invoicing, Forecasting, Joint Use, JUAS, General Separates similar documents across areas
Source System Choice: JUAS, SAP, SharePoint, None Flags documents that can drift from a system

Authoring standards

  • File name: <Area>_<Topic>_<Doc type>.docx, for example Invoicing_FAAP-Approval-Limits_Policy.docx. No dates, versions or FINAL; version history handles that.
  • First paragraph states what the document answers, who it applies to and its effective date.
  • Headings as questions users actually ask ("How is a Z04 order reason applied?").
  • Define PIC terms (JOUA, JUAS, FAAP, CIA, CDP, SEDO, Z04) in 00_Overview and link rather than redefine.
  • Tables for rates and mappings; no scanned images of tables (Copilot in OneDrive does not read images reliably, and scanned text often fails retrieval).
  • Prefer .docx, .pptx, .xlsx, text-based .pdf and SharePoint pages. Convert legacy scanned PDFs or mark them 07_Review Required.
  • No SQL, direct database instructions or unreviewed AI synthesis in grounded folders.

7Runbook: setup

Run these eight steps once, in order; each has a gate that must pass before the next step starts. Tick a gate when it passes; progress is saved in this browser.

  1. 1

    Confirm tenant readiness

    • Ask IT: is KnowledgeAgentScope set to include the PIC site, and do all PIC members hold a Microsoft 365 Copilot licence?
    • Ask IT whether hydroshare.bchydro.bc.ca is indexed by Microsoft Graph.
  2. 2

    Audit permissions before any content lands

    • Site settings > Site permissions: confirm only the PIC Owners, Members and Visitors groups; remove "Everyone except external users" and direct user grants.
    • Library settings: list every item with broken inheritance (the Sundry Billing mirror list is the known, intended exception).
  3. 3

    Build the Knowledge Base library

    • Create the folders in Content and library standards and add the six required columns.
    • Create views: Published, Due for review (Review Date within 30 days), No owner.
  4. 4

    Separate non-authoritative content

    • Move 06_Future State - Draft, 07_Review Required and 99_Archive to a separate KB-Staging library with Members-only access.
    • If staging content must be invisible to Copilot entirely, request Restricted Content Discovery on a separate staging site from IT.
  5. 5

    Migrate legacy content from the network drive

    • Triage in batches of about 500 files: keep (Published), review (07), archive (99) or delete.
    • Deduplicate before upload: one file per topic; the rest go to archive or are deleted.
    • Load large record sets into lists with archive separation, never one list past 5,000 items in a view.
  6. 6

    Configure Site AI settings

    • Set the main agent (ready-made agent until the custom KB agent is approved).
    • Hide the Copilot button from Visitors if Visitors include people outside PIC.
  7. 7

    Build and lock the Knowledge Base agent

    • From the KB library, select Create an agent; sources = Published folders 00 to 05 only.
    • Instructions: answer only from sources, cite every claim, say "not found in the PIC Knowledge Base" otherwise, never give SQL or database steps.
    • Approve it, then break inheritance on Site Assets > Copilots > Approved and give Members read-only access so approved agents cannot be edited or replaced.
  8. 8

    Run the acceptance test

    • Write 20 questions with known answers across areas, including 5 whose answer is only in staging or archive (expected: not found) and 3 that a Visitor should not see.
    • Pass mark: 18 of 20 correct with correct citations, and zero leaks from staging, archive or restricted content.

Review reminder flow (SharePoint-native, compliant)

Create from the KB library via Integrate > Power Automate. Trigger: scheduled recurrence limited to SharePoint actions. Action: get items where Status = Published and Review Date is on or before today plus 14 days; notify each Owner. Notification channel depends on the IT Advisor answer about the Outlook connector; until then, use a list rule or SharePoint alert on the Due for review view.

9Runbook: troubleshooting

Most wrong answers trace to content or permissions, not to Copilot; fix the source, then retest the same question.

Symptom Likely cause Check Fix
Copilot button or Agent icon missing on the site Site outside KnowledgeAgentScope, Restricted Content Discovery on, or no licence Ask IT for tenant scope and site flags; confirm licence IT adds site to scope or removes the flag
Answer cites an outdated document Superseded file still in a grounded folder Search library for the topic; count Published files Archive the old file; set one source of truth
Answer cites a draft Draft stored in a grounded folder or reachable by site-wide Copilot Check Status and folder Move to KB-Staging; recheck Setup step 4
Two users get different answers Security trimming: different permissions Compare each user's access to the cited files Expected behaviour; fix permissions if one user should see more
User sees content they should not Oversharing (broken inheritance, org-wide link, direct grant) Manage access on the cited file Remove the grant; add to permission register; retest leak questions
Agent answers "not found" for a known topic Topic not in agent sources, scanned PDF, or file indexed recently Confirm folder is a source; open file and check text is selectable Add source, convert scan, wait and retest (unverified indexing delay length)
Approved agent behaves differently than tested .agent file edited or replaced by a member Version history on the .agent file Restore prior version; lock Approved folder permissions
Copilot features unavailable mid-day Preview per-user usage limit reached SharePoint shows a limit notice Wait for reset; report heavy-use patterns to IT
Agent Builder agent misses new documents Knowledge list points at specific files, not the folder Review the agent's Knowledge section Point at the folder or library, not individual files
Content from hydroshare.bchydro.bc.ca never appears On-prem host not indexed by Graph IT confirmation (Setup step 1) Migrate needed content to SharePoint Online or exclude from scope

Wrong-answer log fields: date, reporter, question asked, answer given, cited file, correct answer, cause category (content, permission, scope, product), fix applied, retest result.

10Approved prompt patterns

Good prompts name the source, the task and the output format, and ask for citations. Paste these as written and replace the angle-bracket parts. Select a prompt to copy it.

UseWherePrompt
Find the ruleKB agent
Explain a processKB agent
Check freshnessKB agent
Compare versionsOneDrive or library, select 2 to 5 files
Summarize before publishingOneDrive, one draft
Find duplicates during migrationCopilot in SharePoint on the library
Draft a work instructionOneDrive, from notes

Rules for users

  • Open the cited file before acting on any figure, GL code, limit or date.
  • If the answer has no citation, treat it as unverified.
  • Do not paste customer, partner or personal data into prompts beyond what the task needs.
  • Report wrong answers through the wrong-answer log, not by editing the agent.
