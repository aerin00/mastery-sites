Where effort concentrates

Finance owns nearly every coordination step: distribution, follow-up, overlap resolution, consolidation, checking, and report rebuilding.

Why the risk persists

Each emailed copy can diverge. Comments are unstructured, submission status is difficult to see, and the final workbook remains editable after completion.

What this means

The current model is workable, but the control burden grows with the number of projects, managers, and exceptions.

Speaker cue: Emphasize that the problem is duplicated coordination, not that Excel is inherently wrong.

03

Future: one governed forecast cycle

The proposed process separates data preparation, manager accountability, control review, and reporting.

Phase 1

Prepare

  • Pull SAP export manually in version 1
  • Run data-quality checks
  • Correct exceptions before opening
Phase 2

Open

  • Set quarter, due date, horizon, and status
  • Seed one entry per Project × Cycle
  • Pre-fill SAP context
Phase 3

Submit

  • Manager opens “My Forecasts”
  • Enters forecast and signs off
  • System stamps who, when, and version
Phase 4

Govern

  • Track completion and exceptions
  • Reopen records when authorized
  • Lock approved cycle and report live

Before opening

Validate project number, cost centre, dates, active status, and accountable manager.

Data ready?

Only then

Open the forecast cycle and generate manager entries from the approved Project Master.

Accountability shifts to the right place

Managers submit directly into the shared process. Finance controls cycle setup, quality, exceptions, locking, and reporting instead of merging files.

Speaker cue: “The happy path becomes standard. Finance spends time on exceptions and controls, not moving data between files.”

04

Cut-over is controlled, not automatic

The existing workbook remains the benchmark for one parallel quarter.

1 · Pilot

Run in parallel

Execute SharePoint and the current Excel process for the same quarter.

2 · Reconcile

Compare outputs

Validate totals, project-level results, submissions, exceptions, and reporting.

3 · Decide

Numbers match?

If no, correct the design and repeat the agreed test scope.

4 · Retire

Stop emailed copies

Only after acceptance, lock the new process and retire workbook distribution.

Go condition

Reconciled numbers, accepted controls, clear ownership, usable manager experience, and signed-off reporting.

No-go condition

Material mismatches, undefined exception handling, incomplete submissions without a rule, or unclear reopen authority.

Open point: “Correct the design and repeat” does not identify whether to repeat the entire pilot quarter or return to a narrower build-and-test step. Define this before pilot approval.

07

Seven controls must be settled

These are design decisions, not reasons to reject the approach. They should be assigned owners and closed before the pilot.

1
Reopen after lock

Who can reopen an approved cycle, under what conditions, and how is the action logged?

2
Non-submission at lock

Does the cycle wait, lock with an exception, escalate, or use a default treatment?

3
Admin request lifecycle

Define request owner, approval route, statuses, service expectation, and terminal state.

4
Reminder fallback

If automated reminders are not approved, identify the manual owner and cadence.

5
SAP export trigger

Set the owner, timing, file location, version control, and failed-export response.

6
Pilot repeat rule

Define what is repeated after a mismatch and what acceptance thresholds apply.

7
Quarterly return

Confirm the recurring reset from locked reporting back to a newly opened cycle.

✓
Recommended control pack

Record owner, decision, evidence, due date, and approval for each item in one pilot readiness register.

08

Recommended path to a safe pilot

Keep version 1 deliberately narrow, prove the controls, then add optional capabilities.

Gate 1

Confirm design

Validate source documents, list fields, ownership, controls, and success measures.

Gate 2

Build core cycle

Implement five lists, required views, three core flows, and manual SAP loading.

Gate 3

Pilot in parallel

Run one quarter with Excel, reconcile at record and total levels, and collect manager feedback.

Gate 4

Accept or correct

Retire emailed workbooks only after formal acceptance. Defer Financial Hub and optional analytics.

Build now

Core lists, cycle controls, My Forecasts, submission tracking, audit trail, locked reporting, and pilot reconciliation.

Defer until proven

Financial Hub, Copilot, advanced Power BI, automated SAP ingestion, and reminders if approval is unresolved.

Speaker cue: This keeps the first release small enough to govern and gives management a clear stop/go decision after evidence exists.
