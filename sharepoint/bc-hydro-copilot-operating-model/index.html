Microsoft 365 Copilot operating model for BC Hydro workflows

Use Microsoft 365 as an information lifecycle, not as a collection of interchangeable apps. SharePoint is the governed authority; Copilot and collaboration tools are working layers that help retrieve, reason, coordinate, draft, and communicate.

Core rule AI helps create and reason over work. Human review promotes work into the authoritative record.

The safest mental model is permission-aware retrieval over Microsoft 365 content, not a new hidden knowledge base containing copies of everything.

Primary risk: Copilot amplifies existing permissions If SharePoint is overshared, outdated, duplicated, or poorly governed, Copilot can make that mess easier to retrieve. The first Copilot control is therefore permissions and content hygiene, not prompt engineering.

Prompts & discovery

Assume prompts are governable records

Copilot interactions can be subject to Purview retention, audit, and eDiscovery. Do not treat prompts as off-the-record scratch space.

Pages and Notebooks require extra review

SharePoint Embedded caveat Copilot Pages and Copilot Notebooks live in SharePoint Embedded containers and have different governance/lifecycle characteristics from ordinary SharePoint. For projects requiring Information Barriers or highly constrained content handling, suitability must be validated.

Data residency

Storage-at-rest location and processing location are not the same thing. Microsoft documents local-region storage commitments for Copilot interaction content, but actual tenant geography, Multi-Geo, Advanced Data Residency configuration, and BC Hydro’s permitted handling of personal information must be checked against internal privacy/security policy.

7. Pragmatic information architecture

The goal is to make “current authoritative information” obvious to both humans and Copilot.

Library design

Prefer metadata + controlled locations

  • Separate working and approved libraries when practical.
  • Use explicit status values instead of filename conventions.
  • Track revision, issue date, effective date, and supersedes.
  • Assign a document owner for every authoritative artifact.
  • Use sensitivity and record categories consistently.
Avoid

Do not rely on filenames like

FINAL.docx
FINAL2.docx
FINAL_revised.docx
FINAL_revised_USE_THIS.docx

These are weak signals for people and weaker still for automated retrieval.

Promotion rules

FromToPromote when…

Copilot Page / LoopWord / ExcelThe content becomes a formal artifact requiring controlled review.
Word / Excel / PowerPointSharePoint approved libraryResponsible human review is complete and the artifact is ready to become authoritative.
Teams meeting recapDecision log / Planner / SharePointA discussion creates a material decision, commitment, action, exception, or record-worthy outcome.

9. Prompt library

Notebook grounding discipline

Using only the notebook references:

1. Answer the question.
2. Cite the supporting document for every material statement.
3. Identify the document revision/effective date where available.
4. Separate:
   - explicit source fact
   - inference
   - assumption
   - unresolved question
5. If sources conflict, show both rather than choosing one.
6. Mark unsupported conclusions "unverified."

Technical standard comparison

Using only the references in this notebook, compare the currently
effective standard with the previous revision.

Create a table with:

- requirement / clause
- previous requirement
- current requirement
- change type
- effective date
- project artifact potentially affected
- evidence supporting the assessment
- required follow-up
- uncertainty

Do not determine engineering compliance.

For every material statement, identify the supporting source.
If a conclusion requires engineering judgment rather than explicit source
text, label it "requires engineering review."
If documents conflict, show the conflict rather than resolving it.

Weekly project-control briefing

Prepare my project-control briefing.

Show only material changes since the previous reporting period:

1. decisions needed this week
2. milestones that moved
3. new or materially changed risks
4. overdue actions
5. unresolved issues appearing in more than one meeting
6. contradictions between the status report, action register, and meeting records
7. items lacking a named owner

For every item, cite the source.

Meeting close-out

Create a close-out table containing:

Decision | Owner | Action | Due date | Evidence required | Open question

Then identify:
- anything discussed but not resolved
- any action without an owner
- any owner without a due date
- any statement where two participants appear to have different interpretations

Do not infer agreement when the transcript does not demonstrate it.

Design / document review

Review the supplied draft against the supplied requirements.

Do not state that the design is compliant.

Produce candidate review findings only:

Requirement | Draft evidence | Potential gap | Source | Confidence |
Reviewer required

Pay particular attention to:
- requirements with no corresponding evidence
- contradictory assumptions
- undefined terms
- references to superseded material
- numerical values that differ across documents
- unresolved comments from the previous review
- requirements containing "shall", "must", or equivalent mandatory language

Quote only the minimum text necessary to identify the requirement.

Variance analysis

Analyze actual vs forecast.

For each material variance, report:

- metric
- current value
- baseline / forecast
- absolute variance
- percentage variance
- trend over the last six reporting periods
- whether the variance is new, persistent, or recovering
- the rows / fields supporting the calculation

Do not invent a causal explanation.

Separate:
1. findings demonstrated by the data
2. plausible explanations requiring investigation

Create charts only for the five variances most relevant to management.

Researcher prompt

Research this question using both accessible BC Hydro work content
and authoritative public sources.

Prioritize:
1. legislation / regulation
2. regulator material
3. BC Hydro approved material
4. other primary sources

For every conclusion:
- identify the source
- identify publication/effective date
- distinguish source fact from interpretation
- identify conflicts between sources
- state what remains unknown

Do not provide a final legal or regulatory determination.
