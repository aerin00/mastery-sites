PIC Desk: reference guide

How each screen works, what to click, and why it matters. Every section starts with In short (the answer), then In this section (what it covers), the detail, Why your manager should care, and Efficiency and provenance.

Provenance here means being able to show where every number, status and decision came from: which file, which cell, which email, which person, at what time.

Opening the preview

  2. Double-click Open PIC Desk Preview.html. It opens app/preview.html in Edge.

Downloading and adding files

Click Demo files in the purple bar.

  • Download: pick a folder (exports/, data/, sources/ ...) and click download beside a file. Drafts open in Outlook as editable emails (.eml); packages and templates open in Excel; reports open in the browser.
  • Add a file: type a folder (for example sources/mail/2026-10), choose a file, then click Refresh in the app. This is exactly what "saving an email into the folder" does in real use.

Preview versus the real app

Same code. The only difference is where the folder lives: the preview holds it in the browser's memory; the real app asks you once to pick the shared PIC_Desk folder and remembers it. In the real app, Open PIC Desk.html is the launcher and the status bar shows the real folder name.

Why your manager should care

Anyone can see and try the whole tool in five minutes, on any machine, with no risk to real data and no IT request. It turns "trust me, it will work" into a demo people can click.

Efficiency and provenance

Efficiency
Training and review happen before go-live, without booking the Contoso Energy laptop or touching the shared drive.
Provenance
The dummy files use the real layouts, so what you see in the preview (cell addresses, report headers, file paths) is what the real app will cite.

2. How the app works (the basics)

In short: you put files in the right folder, the app reads and checks them, and every change you make is recorded with your name and the time; the app never edits your source files.

In this section
  • The folder is the contract
  • Screen layout and status bar
  • Lists: filter, sort, export
  • Refusals: the red bar
  • How records are stored
  • Email drafts

The folder is the contract

If a file is in the right folder, the app finds it, classifies it and checks it; if not, it does not exist to the app.

FolderWhat goes thereApp access
sources\<area>\<YYYY-MM>\Evidence you place: emails, workbooks, report exports. The period folder is the month the data is "as at" (the Aug-26 PCM file goes in scorecard\2026-08\).Read only (may create a request folder)
config\Rules, cell maps, calendar, email templatesRead and validate
kb\published\ staging\ archive\Knowledge filesRead
data\Records (one change log per operator)Write
exports\Reports, packages, draftsWrite
backups\Daily copies of your logWrite

The app warns when a file name names a different month from its folder (for example Sep-26 in the 2026-10 folder).

Screen layout and status bar

  • Status bar (dark blue): folder name, operator (click change to switch), mode (read-write or read-only), and Refresh (re-reads config, records and folders after you save new files).
  • Tabs: Today, Scorecard, Close, Intake, Requests, JUAS, Forecast, Knowledge, Governance, Settings. One screen at a time.
  • Read-only banner (orange) appears when the folder cannot be written; the referee, search and reports still work.
  • Green bar: confirmation of what just happened, with the file path it wrote.

Lists: filter, sort, export

Every table has a Filter box (matches any column), clickable column headers (sort, click again to reverse), a row count, and Export CSV (writes exports\lists\<list>.csv). Clickable rows highlight on hover and open a detail form.

Refusals: the red bar

When a gate blocks an action, a red bar names what is missing in plain words, for example "Needs an IM reply in sources/requests/REQ-26-S001". Nothing is changed by a refused action.

Try it: Governance > Open Items > click a row > set Status to Closed > Save. Refused: "Needs closure evidence..."

How records are stored

  • Each operator writes only their own log, data\events\<letter>\<YYYY-MM>.jsonl, one line per change with who, when, old value and new value. Two or three people can share one folder without overwriting each other.
  • On open, the app replays every log to rebuild the registers.
  • Nothing is deleted: a record is "voided" with a reason and stays in the audit.
  • Before your first change each day, the app copies your log to backups\<date>\<letter>\ (30 days kept).
  • If two people change the same field of the same record within 15 minutes, Today asks one of them to confirm.
  • An older copy of the app refuses to write once a newer one has written (version guard).

Email drafts

The app never sends mail. It writes .eml drafts to exports\drafts\ from the templates in config\templates\. You open the draft in Outlook, check it, attach any file it names, send it, then click Mark sent on Today. Replies you save back into the right folder become evidence.

Why your manager should care

The design removes whole classes of failure: no server to maintain, no licence, no data leaving the device, no "which version is current" debates, and no silent edits to source workbooks. Control comes from folder access, which Contoso Energy already manages.

Efficiency and provenance

Efficiency
One place to look instead of inboxes and scattered workbooks; refusals catch errors at the moment of entry instead of at month-end.
Provenance
Every change carries operator, timestamp, old and new value. Files are identified by a content fingerprint (SHA-256), so a renamed file keeps its history and an edited "received" file is flagged.

4. Scorecard: Cycle

In short: open a period to get 15 program rows, each Green only when five gates hold (actuals received, forecast changed or confirmed, loaded, tied out, reviewed), with the six questions answered on the same screen.

In this section
  • Opening or showing a cycle
  • The five gates
  • The six questions
  • BD strip and drafts
  • Explaining a line, marking reviewed

Opening or showing a cycle

Scorecard > Cycle. Type the period (2026-08) and click Open cycle (creates the 15 rows once; safe to click again) or Show.

The five gates

GateHow it is set
Actuals receivedComputed: an Actuals input for the program and period, Received or Applied
Forecast changed?Computed: a Forecast input gives Changed; a forecast-confirmation email gives No change confirmed; otherwise Not asked (not green)
LoadedYou tick the Loaded box
Tied outComputed: every referee line for the program Ties, or has an explanation
ReviewedChloe's reply registered as a Review input, or Mark reviewed with a note

The Missing column names the gates still open.

Try it: show 2026-08. Fire Mesh needs only Reviewed; S1 shows Forecast changed? = Not asked. Tick Loaded on Vegetation and watch its Missing column shrink.

The six questions

  1. Latest forecast and who sent it
  2. Programs missing actuals
  3. Inputs received but not applied (over 3 business days)
  4. Tie-out: how many lines tie, differ, lack a source, or are unverified
  5. Forecast changed and confirmed, per program (and who was never asked)
  6. Reviewed and ready: which programs are green

BD strip and drafts

  • BD2: draft provider requests: one email per provider (from Program Owners) asking for actuals and an explicit "no change to forecast".
  • Export cycle-status.html: a static page with the 15 programs and their gates, safe to email.
  • BD6: draft to Chloe (with cycle-status.html to attach) and BD7: draft to Ben.

Explaining a line, marking reviewed

Pick a referee line, type why it does not tie (for example "Mapping pending Marco"), click Explain line; the program can then be Tied out. Mark reviewed needs a note saying who reviewed and how.

Why your manager should care

"Forecast changed?" defaults to Not asked and blocks green. That single rule closes the loop that left Marco's March forecast off the scorecard for 202 days. A program cannot look finished just because nobody asked.

Efficiency and provenance

Efficiency
The six questions are answered on one screen without opening Outlook; provider requests are drafted in one click from the owners table.
Provenance
Each gate points to a registered file or a recorded tick with operator and time; explanations are stored and printed on cycle-status.html.

5. Scorecard: Inputs

In short: every provider file or reply is registered once, by content, with a status (Received, Applied, Superseded, Rejected); a newer file for the same thing supersedes the older one, and you can undo it.

In this section
  • Registering files
  • Classifying emails and odd files
  • Apply, reject, supersede, undo
  • Views

Registering files

Scorecard > Inputs, type the period, click Register new files. Files whose names match a rule in sources.json (for example the PCM summary) are registered with provider, type and received date (the email Date header, or the file date). Registering again adds nothing.

Classifying emails and odd files

Emails and unmatched files appear under Unclassified files. Choose the file, its type (Actuals, Plan, Forecast, Forecast confirmation, Correction, Variance explanation, Review), programs and forecast change, then Classify and register. It is remembered by content, even if the file is renamed later.

Try it: 2026-08: classify RE Scorecard Aug-26 review (Chloe).eml as Review, then check the Cycle tab: Reviewed turns Yes for every program.

Apply, reject, supersede, undo

  • Apply once you have loaded it into the workbook (sets the applied date).
  • Reject needs a reason.
  • A newer file with the same rule, programs, type and period marks the older one Superseded. Undo supersede restores it.

Views

All, Current authoritative, Waiting to apply, Superseded: the same table, filtered.

Why your manager should care

It ends "which file did we use?". The referee reads the current authoritative input, so a corrected PCM file changes the tie-out automatically, and the old one is still there for audit.

Efficiency and provenance

Efficiency
No renaming or moving files; the register does the bookkeeping. Stale inputs surface on Today after 3 business days.
Provenance
Each input records path, content hash, provider, received date and status history; if a received file is edited later, Today flags "evidence changed after receipt".

7. Close

In short: opening a period generates the close checklist with due dates from the business-day calendar; a JE cannot be Submitted without the approver's real reply, Posted without a doc number, or Done without being Posted.

In this section
  • Opening a period
  • Statuses and gates
  • The reply check
  • Radar
  • Trend and materiality
  • BSS draft

Opening a period

Close > Period, type 2026-10, Open period. Both JEs are due WD2 at 14:00 (3-Nov-2026). Quarterly tasks appear only in March, June, September and December; triggered tasks (such as rra) only when you list them in Triggers. Opening twice creates nothing new.

Statuses and gates

Not Started→Waiting Input→In Progress→Submitted→Posted→Done
  • Submitted: needs the approval reply email that passes the reply check (or an override with a recorded reason).
  • Posted: needs the Posted Doc Number in the configured format.
  • Done: JE tasks need Posted; evidence tasks need a linked file; placeholder tasks (B3/JU, Fabrikam Telecom) have no gates yet.
  • Exception: from any open status, needs a note; returns only to the status it came from.

Click a task row, choose Move to, pick the evidence file, fill the doc number or note, then Apply.

The reply check

The evidence must start with RE:, come from the task's approver (not from an operator), and be dated after the request. Otherwise: "This looks like the request, not the reply."

Try it: open 2026-10, click wip-je, move to In Progress, then Submitted with each evidence file and Check reply: the request, the copy forwarded by Sam, and the early reply are refused; RE WIP Accrual JE Oct-26 approval.eml passes.

Radar

The Radar tab lists each expected input (TQ's Unbilled Sets file, Yara's DVeg email, Colette's input) as Present or MISSING in sources\close\<period>\. Draft requests for missing inputs writes chaser emails.

Trend and materiality

The Trend tab reads the package total from the configured cell (JE!F20) for 13 months and flags a change above both 20% and $50,000. With period 2026-10, October is flagged (+80%); March shows missing.

BSS draft

On a JE task, Draft BSS submission writes the email naming the approval reply file to attach. It is refused if the evidence fails the reply check.

Why your manager should care

It targets the BSS rejection pattern (the request mistaken for the approval) and "submitted mistaken for posted". A covering colleague can run WD1 to WD5 from the checklist alone.

Efficiency and provenance

Efficiency
Checklist, due times and chasers are generated; missing inputs show on Today from WD1 instead of being discovered on WD2.
Provenance
Each task stores the approval email, submission date, posted doc number and any override reason, with who and when.

8. Intake

In short: saved request emails appear under Unlogged mail; open one, the app proposes each field and shows the exact line it came from, you confirm, and a request is created with its evidence folder.

In this section
  • Unlogged mail
  • Proposed fields and source lines
  • Confirm or dismiss
  • Email text is only ever text

Unlogged mail

Emails saved in sources\mail\<month>\ (current and previous month) that are neither logged nor dismissed.

Proposed fields and source lines

Click an email. Request type, project code, WBS, customer, amount, PO, billing reason, requester and received date are proposed from rules in intake-rules.json. Each shows its status (Proposed, Unverified when not found, Unmapped when a project code cannot be normalized) and its source line. Edit any value; it changes to Edited. The app never proposes a value that is not in the email.

Try it: open FW Invoice request IC 10470.eml: "IC 10470" becomes IC-10470; the amount shows 9,850.00. Open Invoice request IC-1047.eml: the code is Unmapped, not guessed.

Confirm or dismiss

Confirm and log creates REQ-26-S0nn at stage New and creates sources\requests\REQ-26-S0nn\ for its evidence. Dismiss (not a request) needs a reason. Both are shared: other operators see the email disappear too.

Email text is only ever text

Open Invoice request - script test.eml: the markup and script in it display as plain text and never run. Formula-like text (=HYPERLINK(...)) is neutralised in CSV exports.

Why your manager should care

Every request email becomes one tracked record, typically within the day, with the original email linked. Nothing lives only in someone's inbox.

Efficiency and provenance

Efficiency
Fields are pre-filled; missing information is listed at intake, not discovered at requisition.
Provenance
Each value shows the email line it came from; the request stores the email path and fingerprint.

10. JUAS

In short: one exceptions register with a duplicate warning and a formal-dispute guardrail, a checklist that confirms each JUAS report export by its header, and a workbook compare tool.

In this section
  • Exceptions and retests
  • Formal disputes
  • Report checklist and JPB pre-run
  • Compare workbooks

Exceptions and retests

New→Under Validation→With System Support→Correction Pending→Retest Required→Closed

System Support needs a ticket; Retest Required needs a retest date; Closed needs a closure date. New exception warns when an open item already has the same pole, activity and kind (Create even if duplicate overrides). Retests due sit at the top of the default view.

Formal disputes

An exception of kind "Formal dispute" (JOUA 19.10) carries "flag and escalate, do not answer" and no correction draft is offered.

Report checklist and JPB pre-run

Reports tab, period 2026-10, Check reports: each of the 11 expected reports shows present, missing, or wrong header. In the preview, Report 48 has the wrong header and Report 52 is missing. The line above gives the JPB pre-run date (last working day, before 21:00).

Compare workbooks

Give two workbook paths, the sheet, key columns and value columns, and a tolerance (default 0.01): you get OK and DIFF counts and each differing cell. Read-only. The preview has no pair of rebuild files; add two with Demo files to try it.

Why your manager should care

One item per issue (HJ vs JJ is one record, not three trackers), and a hard stop on answering formal disputes. The compare tool gives an objective "146 OK / 0 DIFF" before a rebuilt workbook replaces the old one.

Efficiency and provenance

Efficiency
Duplicate warnings and a retest list stop repeated work; the report checklist replaces opening 11 files by hand.
Provenance
Exceptions carry evidence, ticket and dates; a report counts only when its header row matches, so a wrong export cannot pass as the right one.

11. Forecast

In short: the app writes one template per manager, validates the returns they email back, applies only clean ones, tracks who has not submitted, and consolidates.

In this section
  • Open a cycle and generate templates
  • Ingest returns
  • Tracking, reminders, lock
  • Consolidate

Open a cycle and generate templates

Enter the cycle (F27Q3), due date and horizon periods, Open cycle, then Generate templates. Each manager of the pilot cost centre gets exports\forecast\<cycle>\templates\<manager>.xlsx listing their active projects once, with a hidden sheet identifying cycle, manager and template version, plus a request draft.

Ingest returns

Returns go in sources\forecast\<cycle>\returns\. Ingest returns checks template version, cycle, missing project, duplicate, unknown project, non-numeric values and lateness. A return with any issue is not applied; a return is applied once.

Try it: Demo files > exports > download a template, fill numbers in Excel, save, then add it to sources/forecast/F27Q3/returns, click Refresh, then Ingest returns. Type "TBD" in a cell to see "non-numeric".

Tracking, reminders, lock

The Not submitted list groups projects by manager; Draft reminders writes a chaser to each. Lock cycle makes later returns Late; Accept late returns (reason) applies them with the reason recorded.

Consolidate

Consolidate writes exports\forecast\<cycle>\consolidation.csv with totals by period, the grand total, and variance to the prior cycle when one exists.

Why your manager should care

Managers never need to open the app, and bad returns are rejected with a reason instead of silently corrupting the consolidation.

Efficiency and provenance

Efficiency
No copy-pasting returns into a master workbook; reminders go only to those missing.
Provenance
Each project's values point to the return file, its fingerprint and its date; late acceptance records who allowed it and why.

12. Knowledge

In short: keyword search over published knowledge files, with drafts kept out unless you tick Include drafts (then labelled DRAFT); plus lists of pages due for review, without an owner, or superseded.

In this section
  • Searching
  • Preview
  • Review lists

Searching

  • Type keywords or a question; titles and headings rank above body text.
  • "Quoted phrases" must match exactly: "notice of dispute" finds the JOUA page; "dispute notice" finds nothing.
  • Filter by process area or knowledge type (from each file's metadata).
  • Tick Include drafts to add staging and archive; each such hit shows DRAFT.
Try it: search "S2 Net New rows": no result. Tick Include drafts and search again: the staging draft appears, labelled DRAFT.

Preview

Click a hit to see the file's text below the results. HTML and Word pages are shown as plain text; scripts in a file never run.

Review lists

Due for review (review date passed), No owner, and Superseded but still in published. Moving a file from published to staging takes it out of default results on the next Rebuild index.

Why your manager should care

Draft or stale procedures stop answering questions by accident: the folder decides what counts as published, and ageing pages surface for review.

Efficiency and provenance

Efficiency
Answers come with the file and heading, so people stop asking the same question twice.
Provenance
Every hit names its file, heading and folder status; owners and review dates come from the page metadata.

13. Governance

In short: Open Items (one list for issues and fixes; closing needs evidence), the Decision Log (D1 to D12 and DL1 to DL6), and an audit view of every change.

In this section
  • Open Items
  • Decision Log
  • Audit

Open Items

New Open Item: title, owner, next action, dependency, due, status. Click a row to edit. Closing needs closure evidence (a file path). Projects imported without an IM raise an Open Item automatically, once.

Decision Log

The v2 decisions marked Carried, Changed or Superseded, and the new DL1 to DL6 marked Proposed with who must confirm them.

Audit

Every change, newest first: time, operator, register, record, and old to new values. Filter by register, record, operator, and date range.

Try it: Audit tab, Record = REQ-26-S001, Filter: its whole life from intake to Pending IM Approval.

Why your manager should care

Decisions and open issues live next to the work they govern, and the audit answers "who changed this and when" without anyone reconstructing it from email.

Efficiency and provenance

Efficiency
One list replaces Open Items, change requests, flags and Planner.
Provenance
The audit is built from the append-only logs themselves, so it cannot drift from what happened.

14. Settings

In short: check that each config file is valid, import reference lists, set program owners, preview or load the legacy migration, and see backups and snapshots.

In this section
  • Config status
  • Reference imports
  • Program owners
  • Legacy migration
  • Backups and snapshots

Config status

Each of the nine config files shows valid or its errors, naming the file and key. A broken file disables only the modules that use it; the app still opens.

Reference imports

Import Projects, DOA approvers and Order Reasons from sources\reference\. The result lists duplicate codes, codes that cannot be normalized, active projects without an IM, and active approvers with a zero limit.

Program owners

Forecast owner, actuals owner and backup per program with an effective-from date. History is kept: "Marco until 23-Jun, Anika from 24-Jun" is one answer.

Legacy migration

Preview migration counts what the old list exports would create (preview: 40 project setups, 15 WBS setups, 5 invoice files, 3 reports) and lists unmapped codes and statuses. Load migration (admin) refuses while a status is unmapped (the preview has "Pending"), and writes one file that can be removed to undo the load.

Backups and snapshots

Last backup date for you. Compact snapshots (admin) saves the current state to speed up opening; deleting snapshots rebuilds the identical state from the logs.

Why your manager should care

Rules live in plain files that can be read, reviewed and versioned; a mistake in one file cannot take the whole tool down. The migration is checkable and reversible.

Efficiency and provenance

Efficiency
Data-quality gaps (missing IMs, zero limits, odd codes) are listed at import instead of found mid-process.
Provenance
Migrated records keep their legacy ID and original project code; the migration is one identifiable file.
