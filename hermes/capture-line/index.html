00The optimal flow

One direction of travel for capture, one for review. Everything crosses the machine boundary as files, never as an API the device does not have.

The one constraint that shapes everything. Third-party cloud sync on Chauvet firmware is manual: only Supernote Cloud auto-syncs, and Google Drive needs a swipe down from the top and a tap on the sync icon. Uploads are raw .note files, with no auto-export to PDF. So the pipeline converts off-device, and the health check has to watch for you forgetting to tap.

Phase 1Prove the transcription before you build anything

One afternoon. The riskiest link in the chain is handwriting to usable Markdown, and no amount of pipeline engineering fixes bad transcription. Test that link alone, by hand.

Create the on-device folder skeleton

Four folders under Note/, nothing deeper. The device is where you capture, not where you organise.

Naming rules that survive OCR and scripting: date or quarter prefix, project codes not prose, lowercase, hyphens, no spaces, no special characters. The filename is the stable ID for everything downstream.

Write one realistic test page

Not a neat sample. Write the way you actually write in a meeting: normal speed, an arrow diagram, an abbreviation, a number. Use two Headings and two Keywords on the page, since sn2md extracts titles, keywords and links from the file and you want to see them land in the output.

Point Drive sync at Note/ and sync manually

On the device: cloud settings, Google Drive, Select Folders to Sync, tick Note. To reach a subfolder, tap the row rather than the checkbox. Then swipe down from the top of the screen and tap the sync icon.

unverified One provider at a time. Documentation says the device syncs with one cloud drive, so running Supernote Cloud and Google Drive together may not be possible. Check the setting on your device before you design around having both. If forced to choose, keep Google Drive for the machine-readable path.

Install the converter in WSL and run it on one file

Copy the .note into the Linux filesystem first. Do not run the tool with its working directory on /mnt/g or /mnt/c: DrvFS mounts throw Function not implemented on some operations and are slow.

sn2md renders each page to PNG, sends it to a vision model (default gpt-4o-mini), and emits Markdown with YAML frontmatter, an image list, and extracted keywords, links and titles. It already targets Obsidian flavour: #tags, [[wikilinks]], mermaid for diagrams, $$ for maths.

Judge the output, then tune model or prompt

Configure at ~/.config/sn2md.toml. If gpt-4o-mini mangles your handwriting, try Gemini, Claude, or a local llama3.2-vision through Ollama before changing anything else. The prompt is the second lever: tell it your abbreviations and that arrows mean sequence.

Gate. Transcription is good enough to be worth keeping without re-reading the original page. If it is not, do not proceed. Fall back to Real-Time Recognition notes on the device for anything that must be text-perfect, and keep the vision model for everything else.

Phase 2Lay the ground: mirror, vault, contract

Three pieces of groundwork the agent will assume: a reliable local copy of Drive, a vault skeleton that is queryable by properties, and a written rule about where an agent may write.

Get Drive onto the machine

Default: Google Drive for Desktop. Least code, mounts as G:, readable from WSL at /mnt/g/. Mark the Supernote/ folder available offline so files are real on disk rather than streamed placeholders.

Runner-up: rclone, if Drive for Desktop's down-sync proves flaky, which is a common field complaint. Use copy, never sync, so a local cleanup can never propagate deletions back to Drive.

Build the vault skeleton

Shallow folders for humans, frontmatter properties for machines. PARA-lite wins here because it matches how the work actually divides, and because an agent should query source: supernote AND status: unprocessed rather than walk a directory tree whose shape drifts.

Never nest the vault inside cloud sync. A vault inside Google Drive or Dropbox produces conflict files and version reverts, because .obsidian/workspace.json churns constantly. Put the vault on the local filesystem and version it with Git. Use Obsidian Sync if you need it on other devices.

Put the vault under Git before an agent ever writes to it

This is your undo button for a bad agent write, and it costs five minutes.

Write the agent write contract

One file, read by every Hermes specialist that touches the vault. Without it, the first agent that decides to tidy a note eats your prose.

Install the Obsidian plugins that pay off

  • Dataview: the reason to be strict about frontmatter. Gives you and the agent one shared review surface.
  • Omnisearch plus Text Extractor: indexes PDFs and images, so archived source pages become searchable. PDF extraction fails on some files and does not run on mobile, so treat it as a complement to sn2md, not a replacement.
  • Supernote (Unofficial) by philips: view and embed .note in the vault with ![[file.note#page=2]], export, and import notes edited today. Verified at 2.8.1, Feb 2026.
  • Templater and QuickAdd: promotion templates.

Phase 3Build the ingest agent

One specialist with one scope: read the mirror, write the inbox. It touches nothing else in the vault, which is what makes it safe to run unattended on cron.

Create the Hermes workspace layout

Schedule definitions in jobs/, mutable progress in state/, scratch in workspaces/. Keeping them apart is what lets you delete state and re-run cleanly.

Write the agent scope file

Non-overlapping scopes are the whole point of the Orchestrator plus specialists architecture. Write the boundary down so the Orchestrator can route without ambiguity.

Skeleton below. The only non-obvious parts are hashing before conversion (cheap, avoids paying for LLM calls on unchanged pages) and writing frontmatter that links the Markdown to both source artefacts.

unverified The supernote_pdf invocation signature is illustrative. supernote-tool convert -t pdf from supernotelib is the fallback if the CLI differs.

Schedule it and commit each run

Gate. Run three times in a row with no new captures. Second and third runs must report processed: 0 and produce no git commit. If they do not, your hashing or your output paths are unstable, and duplicates will accumulate silently.

Phase 4Surface it, and converge with what you already run

Ingest without review is a landfill. The important design decision here is subtractive: do not build a second promotion flow, extend the one you have.

Add a captures section to the morning brief

Per new inbox note: title, keywords, one-line LLM summary. Plus the aggregate: count ingested, count awaiting promotion, ingest errors.

Add the health line

One green, amber or red line. It exists mainly to catch the two silent failures: you stopped tapping sync, and Drive stopped syncing down.

Teach the existing sweep about Supernote notes

Rather than a second sweep, have promote_candidates.py treat source: supernote as one more candidate class alongside Brain-Scribe fragments. Likewise, the end-of-day compile should read notes derived from Note/idea/, so a handwritten scrap and a Telegram fragment go through the same router.

Promotion writes three things: status: promoted, the project or area value, and a move into 20_projects/ or 30_areas/. Everything else stays put.

Make the queue actionable from Telegram

Promote, keep, discard, per note. This is the piece that earns the whole pipeline on days you are away from the desk: capture on paper in a meeting, triage from your phone on the way home, and arrive at a filed vault.

Phase 5Close the loop back to paper

The return leg is what turns the Nomad from a capture device into a review surface. It is also where most people get the page geometry wrong.

Render a weekly review packet at the right size

The screen is 7.8 inches at 1404 by 1872. An A4 page forces zoom and pan; a two-column academic PDF is unreadable. Generate at A6.

  • A6 page, single column, 14 to 16pt body.
  • Wide right margin, roughly a third of the page, for annotation.
  • One item per page, so a marked page maps cleanly back to one note.
  • For long reading material, use EPUB instead: it reflows. Keep PDF only for things you must annotate at a fixed position.

Stage it in Drive and pull it on the device

Write to ~/.hermes/outputs/review-packets/, copy into the Drive Supernote/Document/review/ folder, then sync on the device.

unverified Cloud to device delivery. Third-party sync is documented as device-initiated, and deletion propagation is undocumented. Community consensus treats it as backup rather than true two-way sync. Test one packet before you rely on this weekly, and keep the Partner App or a USB copy as the fallback path.

Get the annotations back

Annotations live in a separate layer and must be exported: three-dot menu, Export, choose original or vector handwriting, choose colour. You get a flattened annotated PDF, not a separable ink layer. Teach supernote-ingest to pick these up from EXPORT/, transcribe the margin notes, and attach them to the originating note rather than creating a new one.

Optional, only if file-shuffling becomes the bottleneck

Stand up allenporter/supernote as a self-hosted private cloud on a NAS: native .note parsing, optional Gemini OCR, semantic search, and an MCP server the Orchestrator can call directly. A beta firmware (3.24.39_beta) also adds WebDAV and a private server app. Both remove the manual sync tap. Neither is worth doing before the file pipeline has proven itself.

Frontmatter contract

These keys are the query surface. Agents read them, Dataview reads them, and promotion writes to them. Nothing else should be load-bearing.

Links. Use [[wikilinks]] for note-to-note so Obsidian repairs them on rename. Use plain Markdown links for attachments and anything external tooling must resolve without Obsidian's link resolver. sn2md already emits image links the second way, which is correct.

RefCaveats and unverified claims

  • unverified Bidirectional behaviour and deletion propagation of Google Drive third-party sync are not officially documented. This design assumes device-to-cloud only.
  • unverified Whether Supernote Cloud auto-sync and Google Drive manual sync can both be active at once. Documentation says one cloud drive at a time.
  • unverified Clean extraction of the annotation ink layer alone. Export produces a flattened annotated PDF.
  • unverified Exact sn2md.toml key names and the supernote_pdf CLI signature. Confirm against the installed version's help output.
  • Tool currency. supernotelib shows a 0.7.0 wheel on PyPI while one advisory site labels it inactive, likely a stale snapshot. The sn2md release date of 18 June 2026 is confirmed, the exact version string is not. The Obsidian Supernote plugin is confirmed at 2.8.1, 14 February 2026; a later tag was reported but not independently confirmed.
  • Source conflict. Some Supernote marketing pages describe third-party cloud sync as automatic. Official support steps and firmware documentation describe it as manual. This guide follows the latter.
  • Anecdote, not vendor position. Reports of Google Drive for Desktop down-sync flakiness are practitioner accounts. Treat as a risk to monitor.
