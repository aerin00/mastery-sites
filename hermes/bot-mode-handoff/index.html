Read the fleet

Observe25–40 minprereq: None
At any moment you can say who is on the roster, who is busy, which rooms are open, and which hard caps bound the next send.

Concepts 5

Bot Mode is a UI over profiles

There is no second primitive. A Bot is a Hermes profile: isolated config, memory, skills, credentials, and chat history under ~/.hermes/profiles//. The default profile lives at ~/.hermes with internal id default and cannot be deleted. Bot Mode ships built into Hermes Desktop and is on by default. The CLI is the same agent: hermes -p chat opens that Bot, and its routines appear in hermes cron list.

If you treat “Bot” as a different kind of thing from “profile,” you will look for a daemon that does not exist and miss the files that actually hold state.

What the roster is showing you

The Bots pane is an activity-ordered list of DM rows and group-room rows. Click a Bot and you land in its canonical Bot Chat, created and pinned the moment the Bot is born. Groups are standalone rows with member count, latest message, and a needs you badge when someone used @user.

The three numbers that bound every group send

Official Bot Mode docs put hard caps on group rooms so they cannot spin. You cannot operate a cascade, a review board, or a “let them pull each other in” loop unless these numbers are in your head before you press send.

CapValueWhat happens at the wall
Bots in a room2–6You cannot seat a seventh specialist in that room
Serial rounds per user send3Further @pulls in the same send do not get another round
Messages per send10The room stops, even if the thesis is unfinished
Settle conditionA full round stays silentPassing is how the room ends, not a failure

The forever-chat invariant

Typing /new or /reset inside a Bot’s canonical chat would fork the relationship into a scratch session — the one thing Bot Mode promises never happens. The composer reroutes it to /compact: fresh working context, same conversation. Regular sessions on the same profile keep full /new freedom. If you wanted a clean slate with that Bot, you compacted; you did not start over.

CLI is not a different fleet

Inventory the same roster from a terminal. If Desktop and CLI disagree, you are looking at two homes or two machines, not two products.

hermes profile list
hermes -p default chat
hermes cron list
ls ~/.hermes/profiles

Lab

Baseline your real roster

  1. Open Hermes Desktop → Bots tab. Write down every visible Bot, every group row, and whether Active now is showing anyone.
  2. From a terminal, run hermes profile list and hermes cron list. Match each Desktop Bot to a profile directory and each routine to a [bot:] job.
  3. Note the three caps on a card or a sticky: 2–6 / 3 rounds / 10 messages.
  4. Break it deliberately: right-click a Bot you actually use → Hide Bot. The row disappears. @mention that Bot from another chat anyway. Confirm the mention still resolves and that any routine on it is still listed in hermes cron list. Then Unhide.
  5. Open that Bot’s canonical chat and type /new. Watch it become /compact instead of a fresh session.

Done when: You have a written inventory (names, paths, rooms, routines) and a confirmed observation that Hide does not stop work.

Gotchas 4

trapHide looks like offHidden Bots never toast, so a quiet fleet can still be burning tokens on routines and still answer @mentions. Display is not a kill switch. Delete Profile is the destructive one; the default profile cannot be deleted at all.
trap/new in canonical chat does not mean newThe composer succeeds and you get a compacted forever-chat. It looks like a reset. It is not. History is still the same conversation.
costActive now is a 90-second ghostA Bot that finished 91 seconds ago is gone from the strip. Do not use presence as “who owns this.” Owner lives in your prompt or in a Kanban row, not in the chip.
okThe roster is working memory, not the archiveLatest-message previews are for navigation. Decisions that must survive compaction belong on Kanban, in a note, or in a skill — Phase 10.

Checkpoint 4

Name the three hard caps of a Hermes Bot Mode group send, and the settle condition.
2–6 Bots per room. Up to 3 serial rounds of member turns per user send. 10 messages per send. The room settles when a full round stays silent.
Where does a named Bot’s config, memory, skills, and chat history live on disk? What is the exception?
Under ~/.hermes/profiles//. The default profile is not in profiles/; it lives at ~/.hermes with internal id default, and it cannot be deleted.
What happens when you type /new or /reset inside a Bot’s canonical Bot Chat?
The composer reroutes it to /compact: fresh working context, same conversation. Bot Mode refuses to fork the canonical relationship into a scratch session.
Name three things that keep happening after you Hide a Bot.
@mentions still resolve. Group memberships are untouched. Routines keep running. Hidden Bots also keep accumulating unread activity without toasting.
